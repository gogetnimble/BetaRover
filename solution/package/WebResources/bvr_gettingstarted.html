Getting started

Ember

Ember crawls your tenant for Power Automate cloud flows and code-reviews them against a delivery standard you control — then lets you unit-test the flows and track their health over time. This guide covers what each area does and how to get going.

What Ember does

Reviews flowsA nightly crawl (or on-demand run) scores every cloud flow against your standard and records the findings.
Standards you ownRules, thresholds and severities live in Dataverse — change them without touching code or redeploying.
Unit-tests flowsAuthor mocked test cases and run them in-browser to confirm a flow behaves — no live connectors called.
Tenant-wide viewFilter everything by environment; track score trends, compliance and test health on the dashboard.

Everyday use

Read the dashboard

Start on Dashboard. The tiles summarise the latest review run: average score (with the change vs the previous run), how many flows are compliant, open findings, and unit-test pass rate. The By environment card breaks the numbers down per environment.

Open a flow's review

On the dashboard or Flow Reviews, click a flow to see its findings — each rule's pass / warning / fail, the evidence, and how to remediate. AI observations (if enabled) are listed separately.

Run a review on demand

From a flow's review, Run review now queues an on-demand run for that single flow and refreshes when it finishes — useful right after you've changed a flow.

Tuning the standard

Under Configuration → Review Rules you'll find the active standard and its rules. Every threshold — the naming prefix, the approved email sender, the required scopes, the $top row count — lives in a rule's Parameters. Change a value and the next crawl uses it: no code change, no redeploy. Severity and weight drive the 0–100 score. Use New rule to add your own criterion.

Unit-testing a flow

  1. Add a test case. On Flow Coverage or Test Cases, click New test case. Pick the flow, then use the guided builder to pin the trigger outputs, mock connector actions (their outputs & status), seed variables, and add assertions (action ran / status = / variable = / …).
  2. Run the tests. On Flow Coverage, click Run tests for a flow. Ember reads the flow's definition and executes each case through an in-browser mock runner — no live connectors are called.
  3. Read the result. A pass/fail result is written to Test Runs, and the flow's last test pass date and the dashboard's unit-test tiles update.

Licensing

Use Configuration → License to send your email and any comments (seat count, environments in scope, questions). It reaches our team and we'll follow up by email.

Admin: first-time setup

If you're standing Ember up for the first time:

  1. Import the solution (Ember_1_0_1_0.zip) — brings in the publisher and the web resource(s).
  2. Provision the tables & choices — run the provisioner (browser console or Node) to create the 8 tables, 10 global choices and the seed standard.
  3. Build the model-driven app — add the web resource and the site map (the three groups above), with an icon per item.
  4. Wire the crawl — build the Crawl Orchestrator flow and the review connector/engine so runs populate the data.
  5. Grant access — give reviewers the Flow Review security role (Read on the bvr_* tables; Create where they'll add rules / test cases / runs).
Until the crawl has run, the grids are empty and the Environment filter lists only environments that already have flows in the inventory — that's expected on a fresh setup.
